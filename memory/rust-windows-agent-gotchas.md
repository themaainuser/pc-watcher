# Rust / Windows / ETW gotchas (verified in PC-Watcher)

- 2026-10-24: tao's event loop `run` is `-> !` — closures given to it are NEVER dropped, so any `Sender` clone captured by tray/menu handlers lives for the whole process. Shutdown logic must use an explicit stop flag/sentinel; channel-`Disconnected` as the primary stop trigger hangs forever (reviewer proved it with a standalone repro).
- 2026-10-24: `UnhookWinEvent` must be called from the thread that installed the hook (MSDN) — calling it from another thread is a silent no-op. All WinEvent/WTS/Power notification teardown belongs in post-loop cleanup on the hook thread itself; the handle's `stop()` just posts `WM_QUIT` + joins.
- 2026-10-24: ferrisetw wraps callback dispatch in `catch_unwind` and calls `std::process::exit(1)` on panic — any panic in an ETW callback (including poisoned-mutex `.expect()`) kills the always-on agent. Repo convention: `unwrap_or_else(|e| e.into_inner())` poison-tolerant recovery in all callback threads.
- 2026-10-24: `PostThreadMessageW(WM_QUIT)` fails with ERROR_INVALID_THREAD_ID if the target thread has no message queue yet — create the queue (`PeekMessageW(PM_NOREMOVE)`) before signaling readiness from the spawned thread.
- 2026-10-24: every port from both ETW properties and `GetExtendedTcpTable` is network byte order — convert with `u16::from_be`; a missed swap shows up as 443 reading as 47873.
- 2026-10-24: leftover ETW session name after a hard kill makes the next `.start()` fail forever — always `stop_session(SESSION_NAME)` before every `run_session` attempt.
- 2026-10-24: `RegisterClassW` ERROR_CLASS_ALREADY_EXISTS (1410) for your OWN class = reuse, not failure; do full teardown (DestroyWindow, UnregisterClassW, WTSUnRegister, unhook) on the hook thread so start→stop→start works in-process (regression test `os_restart.rs` proven non-vacuous against the old base).
- 2026-10-24: `ControlTraceW` query-loss buffer must be alignment-backed (`Vec<u64>`, not `Vec<u8>` cast) with the logger name written via `ptr::copy_nonoverlapping` after the pointer is established.
- 2026-10-24: SQLite WAL + busy timeout is what lets a read-only dashboard (`Store::open_readonly`) coexist with the agent's writer; never hold a read transaction across UI refreshes; release the store lock between 50k-row prune chunks.
- 2026-10-24: Exit-hang seam class: shutdown joins a worker thread FIRST while that thread's inner "delete-until-zero" loop only checks the exit flag in its OUTER loop — join-order × uninterruptible-inner-loop is invisible to task-scoped reviews (loop reviewed separately from join order). Check the flag inside EVERY inner loop a shutdown joins.
- 2026-10-24: Lifetime-cumulative counter seeding: when resuming a supervisor from persisted totals, seed the TOTALS but keep the comparison BASELINES at 0 — seeding baselines too stalls the delta math (`+= session − baseline`), plain re-publishing zeros overwrites the loaded values within one tick (both failure modes observed in review).
- 2026-10-24: Inert config keys are a recurring drift: a key can be parsed, defaulted, tested and documented yet have zero read sites (`export_schedule` hardcoded 7 days in the timer). Grep every spec/README config key for a real call site before calling it done.
- 2026-10-24: Per-PID maps fed by both start AND stop events grow unbounded (nothing ever removes stop-entries); wholesale clear-on-cap is safe when entries re-derive from the next ETW event — `CACHE_CAP = 10_000` clear-after-insert still answers the current lookup correctly.
